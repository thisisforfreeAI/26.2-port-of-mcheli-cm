# Fabric build — plan and status

> **Status (2026-11-02): stages 1–3 of 5 done, stage 4 under way.** The Fabric jar builds, and a
> **Fabric dedicated server boots**: it loads all the stock content (120 items), generates the
> content recipe pack, spawns and ticks every stock vehicle, and registers `/mcheli` and `/wingman`
> (`./gradlew -PwithFabric :fabric:runGameTestServer`, also a CI job). Server systems listen on
> the shared `GameEvents` hub, and client systems on `ClientEvents` (ticks, frames, camera angles
> and FOV, input, HUD layers, world geometry), which Fabric fires from Fabric API events and
> client mixins. **The Fabric client is not usable yet**: the **21 files in
> `fabric/neoforge-only.txt`** (render pipelines, particle groups, key mappings, entity renderers
> and menu screens registration, the client entry point) and the client files in
> `fabric/client-pending.txt` that call into them are left out of the Fabric jar. NeoForge is
> unchanged for players (all 297 GameTests pass).

## 1. Shape

One repository, one source tree, two loader builds. No mass file move:

| Path | What it is |
|---|---|
| `src/main/java`, `src/main/resources` | The mod. Shared by both builds. The NeoForge build (root project) compiles all of it. |
| `src/main/java/.../platform/Platform.java` | **The seam.** Everything loader-specific the shared code needs: registration, fuel fluid objects, menus with extra data, payload sending, mod files, config screen, game/config folders. |
| `src/main/java/.../platform/neoforge/` | NeoForge implementation and entry point (`NeoForgeMod`, `NeoForgePlatform`, `NeoForgeNetwork`, `NeoForgeFluids`). Left out of the Fabric build. |
| `fabric/` | Gradle subproject (Fabric Loom). Compiles `src/main` minus `platform/neoforge/` and minus the files in `fabric/neoforge-only.txt`, plus its own glue in `fabric/src/main` (`FabricMod`, `FabricClientMod`, `FabricPlatform`, `FabricNetwork`, `FuelFluid`). |
| `src/main/java/.../platform/loader/` | **Split classes**: a class that needs a different superclass per loader (`SpawnDataEntity`, `PartEntityBase`, `ModBlockEntity`) exists in both source trees with the same name and API. The Fabric build leaves out the `src/main` copies. |
| `fabric/src/main/java/.../fabricmixin/` | Fabric-only mixins that recreate NeoForge hooks: part entities in entity lookups and `getEntityOrPart`, spawn data after the add-entity packet, saved data without a data fixer. |
| `src/main/java/.../platform/GameEvents.java` | **Loader-neutral game events** (server/level/entity ticks, server start/stop, entity join, logins, commands, entity interaction, pack finders, tags). Shared code adds listeners in `McheliCePort#registerEvents`; `NeoForgeEvents` and `FabricEvents` (plus two Fabric mixins: entity ticks, pack repositories) fire them. |
| `src/main/java/.../platform/ClientEvents.java`, `HudLayers.java` | **Loader-neutral client events** and HUD layer registration. `client/ClientSetup` adds the listeners; `NeoForgeClientEvents` and `FabricClientEvents` (plus the mixins in `fabricmixin/client`: frames, camera angles with roll, camera distance, FOV, the hand, name tags, keys, attack/use, mouse wheel, client entity ticks, after-level) fire them. |
| `fabric/neoforge-only.txt` | Generated by `python3 fabric/update-neoforge-only.py`: shared files that still use NeoForge APIs Fabric lacks. **Stage progress = this list shrinking to zero.** |
| `fabric/client-pending.txt` | Client files that compile only once the files they call in `neoforge-only.txt` are ported (found by compiling). Empties with stage 4. |

Why not a `common/` + `neoforge/` + `fabric/` split now: it would move all 894 files, break every
open branch and the build/test scripts, and buys nothing until the glue is behind the seam. Once
`neoforge-only.txt` is empty, the split is a mechanical `git mv` (and the 1.21.1 backport can reuse
the same seam).

Each loader names its `Platform` implementation in `META-INF/services/io.github.mcheliceport.platform.Platform`.

### Build

- `./gradlew build` — NeoForge only, as before.
- `./gradlew -PwithFabric :fabric:build` — the Fabric jar (`fabric/build/libs/mcheli_ce_port-fabric-<version>+fabric.jar`). Server-only so far: the client code is left out until stage 4.
- `./gradlew -PwithFabric :fabric:runGameTestServer` — boots a Fabric server headless and runs `FabricServerGameTests`.
- Gradle is now **9.8.2** and runs on **Java 25** (`gradle/gradle-daemon-jvm.properties`): Fabric Loom 1.19 needs both. ModDevGradle 2.0.148 builds and runs the GameTests unchanged on it.

### Dependencies on Fabric

| Need | Fabric side |
|---|---|
| Registries | `Registry.registerForHolder`, eager, at init (`FabricPlatform#register`) |
| Configs (`ModConfigSpec`, config screen) | **Forge Config API Port 26.2.1** (required dependency): ships NeoForge's config classes under the same names, so `config/*` compiles unchanged |
| Networking | `PayloadTypeRegistry` + `ServerPlayNetworking`/`ClientPlayNetworking` |
| Menus with extra data | `ExtendedMenuType` carrying the NeoForge-style buffer as a byte array |
| Access transformer | `fabric/src/main/resources/mcheli_ce_port.classtweaker` (same entries) |
| SnakeYAML | Jar-in-Jar (`include`) |

## 3. Stages

1. **Done — build + seam.** Fabric subproject, Gradle/Java bump, `Platform` seam for registries,
   fuel fluid, menus, networking, mod files, config screen; Forge Config API Port; Fabric entry points.
2. **Done — vehicle core.** Multipart hit boxes, spawn data, fluid/energy seam, saved data, block
   entity load hooks, creative tabs. Fabric compile errors went from 3,824 to 408, all of them
   references to the files still in `neoforge-only.txt`.
3. **Done — server events.** `GameEvents` hub fed by both entry points; chunk tickets, fake
   player, persistent data and the other server-side extensions behind the seam. The Fabric jar
   builds (client code parked in `client-pending.txt`), and its GameTest server boots with the
   content loaded, every stock vehicle spawned, the generated packs enabled and the commands
   registered. CI runs it.
4. **Client.** Renderers, HUD layers, world-render hooks, key mappings, screens, particles.
   Goal: in-client QA on Fabric (fly, fight, crash a plane).
5. **Parity + release.** GameTests on Fabric, CI job, CurseForge/Modrinth Fabric files, and then the
   `common/neoforge/fabric` folder split.

Rule for every stage: after each change, `./gradlew build runGameTestServer` stays green on
NeoForge, and `python3 fabric/update-neoforge-only.py` shows the list shrinking.
